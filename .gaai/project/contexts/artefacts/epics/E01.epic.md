# Epic: Client Fingerprinting & Access Control

## Purpose

Umožnit identifikaci a kontrolu, odkud je API klíč skutečně používán. Zvýšit viditelnost do volajících klientů a umožnit omezení přístupu na základě fingerprint dat.

---

## Scope

1. Sběr a evidence maximálních informací o volajícím (User-Agent, MCP clientInfo, IP, TLS metadata)
2. Implementace opatření na základě evidovaných dat (validace UA patternu, anomaly alerting, povinný clientInfo)

---

## Out of Scope

- mTLS / client certificates (vyžaduje infrastrukturní změny)
- TLS fingerprinting na úrovni reverse proxy (JA3) — může být follow-up

---

## Stories

> Stories are tracked in the backlog. This list is descriptive only.

- E01S01: Rozšířený sběr identifikačních dat volajícího
- E01S02: Opatření a enforcing na základě identifikačních dat

---

## Success Metrics

- U každého API volání je v audit logu kompletní fingerprint (UA, clientInfo, IP)
- Admin může per-klient nastavit expected UA pattern a dostane alert při odchylce
- MCP klienti odesílají clientInfo při initialize a tato data jsou uložena
